## Architecture (src/solar_glare/)

- `profiling.py` — **opt-in run profiler (added 2026-09-26), observation only, never feeds the physics.** `StageTimer` records per stage `wall_s` (inclusive) and `self_s` (exclusive of nested stages), `calls`, declared key outputs, and the sub-panel task spans of the one parallel region; accumulators are **thread-local** so `analyze_pair`'s `ThreadPoolExecutor` is measured without a lock and without perturbing thread scheduling. `STAGE_SPECS` (45 entries) is the registry giving every stage a `phase` (`config`/`site`/`solar`/`analysis`/`io`/`figures`), a one-line `does`, an `outputs` tuple of `(name, unit, stored_in)`, and a `persisted_in` note; `PHASE_ROOT` names each phase's root stage. **Suppression rule:** an output whose `stored_in` is non-empty is NOT rendered in `key_outputs`, because that number is already in another CSV/PNG — the profile records timing, not results. `TIMER` is the module-level handle the instrumented code calls; `set_timer(None)` / `enabled=False` swap in a shared `_NULL` context yielding a no-op handle (`.key()`/`.parallel()` absorb silently) so **the validators run with ~0.2 µs/stage overhead and their bit-identity checks stay meaningful**. Two non-obvious mechanisms: **(a)** `phase_frame()` subtracts the root's `foreign_s` (time the root spent hosting a *different* phase) so the phase times are a true disjoint partition — necessary because `compute_ephemeris` is both a `solar` phase root and a child of the `analysis` root `run_analysis`, so naively adding root wall times double-counts ~8 s/case; **(b)** `stop()` freezes `total_wall_s`, without it a timer keeps accumulating through the rest of the sweep (which is why `run_case`/`main` call it). `stage_fn(name)` is the decorator form used on the leaf helpers in `geometry.py`/`hazard.py`/`iec62471.py`. **General per-call timeline (added 2026-09-27):** `_StageCtx` also records EVERY stage entry/exit into `_call_spans` as `(span_id, parent_id, stage, t0, t1, self_s, thread_token, depth)`, exposed by `call_span_frame()` / `call_span_count()`; parent links are **thread-local** (a worker's `_analyze_single` is a depth-0 root, and main's `analyze_pair` is NOT its parent). `run_analysis.py` writes these to `output/<label>/results/run_spans.csv` with `phase`/`thread_label`/`case` columns and `float_format="%.6f"` (1 µs). **Identity gotcha:** `analyze_pair` builds a NEW `ThreadPoolExecutor` per `(array, receptor)` pair, so a case creates ~`65 x 16 + 1 = 1041` `Thread` objects and `threading.get_ident()` is recycled — identity comes from a strong reference to the `Thread` object (`_token`/`_thread_refs`), and `thread_labels()` maps the tokens onto **reusable display lanes `main` + `W1..W16`**, not persistent OS threads. Cost is nil: the 6-case sweep is 662.6 s / 106.9–116.4 s per case, same as before the recorder, and all 27 non-profile result CSVs stay bit-identical. Outputs: `output/<label>/results/run_profile.csv`, `output/<label>/results/run_spans.csv`, `output/<label>/figures/14_run_profile.png` (4 panels: phase bar, per-function log bars, thread-lane chart of the first pair's 18 sub-panel tasks, key-output table), and `output/run_profile_all_cases.csv` for a sweep (config parsing is paid once and appears under the `__once__` pseudo-case). Panel (b) is deliberately labelled as summed over threads, since parallel-stage self time (~700 s) legitimately exceeds the case wall time (~110 s).
- `solar.py` — hourly-or-per-minute sun position via **pvlib NREL SPA** (`SOLPOS_METHOD="nrel_numpy"`, ±0.0003°) + DNI for the full year. SPA is deliberately pinned: the paper's simplified Duffie & Beckman model (SGHAT v6 §4.1) has a misprinted equation-of-time (+16.4 min vs true −11.2 min on 21 Jan) and no refraction (~7° elevation error near horizon, ~0.9° at noon on our site). Pressure default = `alt2pres(altitude)` for a correct refraction correction — **do not downgrade to `method="ephemeris"`**. DNI defaults to pvlib Ineichen clear-sky (`environment.dni_mode: "ineichen"`); `"constant"` + `environment.dni_constant_wm2` (default 1000 W/m²) reproduces the SGHAT/ForgeSolar rule-of-thumb DNI for apples-to-apples benchmarking only — detection (sun position) is unchanged.
- `geometry.py` — ENU vector math: sun vector, panel normal, mirror-law reflection. **Reflection convention:** `reflect()` returns the outgoing light-travel direction `r = 2(s·n)n − s` (NOT the `s − 2(s·n)n` of some texts, which is the reverse vector). Physical consequence: a south-facing panel in the tropics reflects the low morning (east) sun **west** and the afternoon (west) sun **east** — so a morning-glare tower sits WEST of a south-facing array. Verified by sanity checks.
- **Polygon detector (`geometry.py::glare_polygon_hit`)** — true full-width flat-rectangle "polyhedral emanation" hit test behind `hit_test_mode: "polygon"`. Panel ENU corners → unit directions from the receptor → mirror-reflected (per-corner normals); the receptor is hit iff the sun direction falls in the resulting spherical polygon diluted by β/2. Rectangular panel edges are exact great-circle arcs (a straight edge + the receptor span a plane through the sphere centre); test = edge half-space inside-orientation + angular distance to each edge arc for the β/2 offset. Accepts an optional `subset` boolean mask over the time axis for the pipeline pre-cone. `glare_polygon_hit_inf` (chip version, same math) drives the `validate_charts.py` samples for identical mirror-step geometry.
- `hazard.py` — Sandia SGHAT ocular thresholds (Ho 2011, JSEE 133:011011): `E_r = E_c·d_p²/(f²x²)·τ`, burn threshold `0.118/x`, afterimage `3.59e-5/x^1.77`. Classification G/Y/R. Unit convention: DNI in **W/m²** → `corneal_irradiance` divides by 1e4 (1 m² = 1e4 cm²) so `E_c` comes out in **W/cm²**; `retinal_irradiance` keeps that unit (m/rad ratios cancel). The whole drag path is **pointer events** (`pointerdown`/`pointermove`/`pointerup`/`pointercancel`), not mouse events: `mousedown` on the canvas with `mouseup` on `window` was the original trap, because a release outside the window fires neither — and `blur` does not either, since the window is still focused (blur only happens on an app switch). `cancelDrag()` also fires on Reset, Escape and mode switches. A gutter press is recorded in **`press`**, not `drag`: the gutter is a click target (lane isolate / case focus) and routing it through `drag` alone meant a gutter press armed nothing, so the click that followed fell through the release guard and vanished. `pointerup` ignores non-primary buttons, and `contextmenu` cancels the drag — a right-button release while a left drag is armed is not the end of that drag. The canvas carries `touch-action:none; user-select:none` so a drag cannot turn into a page scroll (`pointercancel`) or a text selection (which can swallow the release). `scripts/validate_timeline_html.js` drives all of this through   **real** DOM listeners (the old stub swallowed `addEventListener`, so the band checks were never even

## Key gotchas

- **Hazard classification happens only for glare-hit minutes**; non-hit minutes are `N` (no glare), so heatmaps are mostly white.
- **Hit detector is config-switchable (`environment.hit_test_mode`: `"circular"` vs `"polygon"`)** — `"polygon"` (full-width flat-rectangle polyhedral emanation) is the current validated detector; all headline case numbers above are polygon. Code-level defaults are legacy (`hit_test_mode="circular"` in `geometry.py`, and `_analyze_single` previously defaulted `reflectivity_mode="constant"` behavior — the committed `config/site.yaml` explicitly sets `hit_test_mode: "polygon"` and `reflectivity_mode: "solar_weighted"`; if keys are missing, the code falls back to those legacy defaults). Legacy `"circular"` under-reports elongated-panel glare because the per-sub-panel area-equivalent circle drops the axial extent — live QA on the current config: `obs_ptt` **circular 58 vs polygon 489** min (8.4×) at 1.6 km, `west1_route_1` **circular 98 vs polygon 152** (1.6×) at 15.3 km (validate_charts C2), so the error grows sharply as the receptor gets closer and the far-field route points are nearly unaffected; the ring-era figures (circular 94 vs polygon 851) are historical and must not be quoted as live. Polygon's great-circle boundary is verified 0-FP/0-FN against fine-grid sampling on both a near-field and a far-field receptor (validate_charts [C]); the ring-era tilt-5 config had missed ~0.12% of grazing sub-panel edge minutes, but no such miss reproduces on the current receptors. The far-field route/terminal/obs receptors are largely unaffected by either mode and the former near-field vehicle row (10 m west, commented out 2026-09-22) was where `groups>1` + polygon detection actually mattered.
- **Reflectivity is configurable per run via `environment.reflectivity_mode`** (`config/site.yaml`): `"constant"` (per-array `specular_reflectivity`, e.g. 0.08, at every angle) vs `"solar_weighted"` (ASTM E903-20-style Fresnel model in `hazard.py::solar_weighted_reflectivity`, selected via `environment.glass_type` = `smooth` default | `smooth_arc`; per-array reflectivity is IGNORED). **`"aoi"` (SGHAT v6 Table 1 fit) is NO LONGER a pipeline mode** — removed 2026-09-25; `aoi_reflectivity`/`GLASS_FITS` remain in `hazard.py` as reference-only for the validators. The E903 model only matters where glare actually occurs — on the current config glare sits at **AOI 78.8–82°, E903 solar-weighted ρ ≈ 0.32–0.38** (`obs_ptt`/`west1_route_11` at az098 and `west1_route_1`/`west1_route_2` at az278; the former `vehicle_1..3` were at az278, sun el ~16.6–21.4°), which is ≈ ×1.58 the old SGHAT AOI fit (~0.19–0.27 at that band) — hence the no-extinction peaks rose ~1.5× (0.976→1.537 / 0.984→1.550 / 11.408→17.985 / 8.327→13.128 W/cm²) with hit minutes and G/Y/R verdicts unchanged (all Yellow); those no-extinction baselines were REMOVED from config on 2026-09-25 and now appear only as conservative upper bounds in report §5.1/§5.2; the grazing AOI clip (`_AOI_DEFAULT_MAX = 89°`) and the SGHAT smooth-glass checkpoint values only matter to the reference-only `aoi_reflectivity` now. Switching `glass_type` `smooth`→`smooth_arc` shifts the E903 ρ at those AOIs (smooth_arc R(80)≈0.336 vs smooth 0.390); with hit minutes unchanged. In the committed Beer–Lambert runs attenuation wins at range (az278 route_1 flips Y→G — the only G/Y/R change vs no-extinction, §5.2). Per-pair detail CSVs carry `aoi_deg` + `reflectivity_used` so the hazard can be traced back to the exact reflectivity that produced it (independent cross-check: `scripts/validate_e903.py`).
- **Atmospheric attenuation is configurable per run via `environment.atmospheric_attenuation`** (`config/site.yaml`): `"none"` (default, SGHAT/FAA convention — flat-panel beam stays collimated so E_c = ρ·DNI at any distance, **no inverse-square law**) vs `"beer_lambert"` which multiplies E_c (and so E_r, G/Y/R, IEC t_max) by τ=exp(−σ·d_km) using the **Kruse–Kim hybrid visibility model** `σ=(3.91/V)·(λ/550)^(−q)` [1/km] (Kruse `q=0.585·V^(1/3)` for haze, **Kim `q=0` for fog** — `references/Atmospheric_Optical_Attenuation_Model.txt`) with q: V>50→1.6, 6<V≤50→1.3, 1.2<V≤6→0.585·V^(1/3), V≤1.2→0 (`hazard.py::extinction_coefficient`/`atmospheric_transmittance`; knobs `visibility_km` default 20.0, `attenuation_wavelength_nm` default 550.0). Each receptor uses its **real slant distance** to the array (near field barely moves, far field drops hard — see the headline results above). **Homogeneity caveat (ver2 Sec 6.1):** σ is assumed constant along the whole path, which is only valid to ~5 km; real aerosol density falls with altitude, so far-field τ (>5 km, e.g. west1_route_1/2 at 14–16 km) is order-of-magnitude and would need exp(−∫σ(s)ds) over a vertical profile for formal use. Detection (sun/geometry) is ρ- and τ-independent, so **hit minutes never change** — only hazard irradiance scales. Detail CSVs carry `atmos_transmittance` (1.0 when mode none); validated by `sanity_checks.py::test_beer_lambert_attenuation` (known-answer V=20km, λ=550, d=1km → σ=0.1955 km⁻¹, τ≈0.8224).
- Reflection direction is fixed by `r = 2(s·n)n − s` (see geometry.py note): a south-facing panel with the sun in the southern sky reflects it back **south** (mirror-like), so glare is seen by receptors SOUTH of the array, not north; a low east (morning) sun reflects **west**, a low west (afternoon) sun reflects **east**. Check the desired approach bearing against this before assuming which side of the array is at risk.
- **Back-face test gotcha** (validate_sghat.py [C]): a panel tilted 20° south has a normal pointing mostly **up**, so a high sun from the north still illuminates the front face and reflects north legitimately. A true "sun behind panel" case needs a low north sun (elevation < tilt) so `s·n < 0`.
- **Front-face sun-disc guard** (`_analyze_single`): a hit now requires the whole sun disc above the panel plane (`s·n > sin(β/2)`, `β = θ_sun + 12σ`). This kills the degenerate grazing case (tilt≈0 + sun on the horizon, e.g. `s·n ≈ 0.0005`, DNI ~0.3 W/m²) where part of the reflected cone would appear to come from behind the array — SGHAT v6 documents **no** such gate, so this is a conservative fix, not a standard requirement. There is also an optional DNI floor `environment.min_dni_wm2` (default 10 W/m²) dropping glare minutes with negligible sunlight; set to 0 to disable. Verified in `sanity_checks.py::test_front_face_sun_disc_guard` (tilt≈0 grazing sun → N; clearly-lit sun → hit). Current tilt-10 hits (`obs_ptt`/`west1_route_11` at az098, `west1_route_1`/`west1_route_2` at az278) are unaffected.
- Default resolution is **per minute** (`site.time_freq: "min"` → 525,600 steps); set `"h"` for 8,760-hour runs. G/Y/R counts and `minutes_with_glare` follow the chosen freq. Figure units are chosen per chart: daily duration (06) in min/day, summary bars (07) converted to **hours** (`/60`, "Hours per year"), site map (02) annotates min or `h m` (`_fmt_minutes`), heatmap (05) is **30-min resolution** (365×48 cells, y tick labels stay hourly 0:00–23:00). CSV output (`glare_events.csv`, per-pair `glare_hours_*.csv`) stores **glare rows only** — non-glare minutes are omitted.
- **Ocular chart (08) auto-extends its x/y limits to the data** (`viz.py::plot_ocular_chart`): far-field array-limiting angles can fall below 1e-3 rad and their sharp retinal image can exceed 1e2 W/cm² (a historical demo peak hit 1,071 W/cm² @ x=0.3 mrad) — clipping used to hide the worst point. On the current config the az098 hits are sun-disc-limited (x = β = 9.3 mrad, peaks 1.109/0.602 W/cm²) while the far-field az278 hits sit at x ≈ 2.78/3.25 mrad with peaks 0.847/0.959 W/cm² (the no-extinction upper bounds, now only referenced in report §5.1/§5.2, were 1.537/1.550 and 18.0/13.1 W/cm²). Do not hardcode `set_xlim(1e-3, ...)` back, or re-clip the peak hazard point.
- **`run_analysis.py` does not clean `output/results/`** — it overwrites `summary.csv`/`glare_events.csv` and per-pair files that still have glare, but stale `glare_hours_*.csv` from older grids/runs linger (e.g. R5x5/R25x25, pre-§5.5 pairs). Trust only `summary.csv` + `glare_events.csv` of the latest run; prune stale per-pair files by matching names against the current `config/site.yaml` receptors or the pairs in `glare_events.csv`. **With `site.cases` set, each case runs into its own fresh `output/<label>/{figures,results}`** (label + azimuth_deg per case; azimuth overridden on every array) so cases never cross-contaminate and stale figures are cleared per case.
- **`groups` มีผลเฉพาะ detection footprint (near/medium-field); hazard ไม่ขึ้นกับ `groups` เลย** — หน้าต่างการชน `beam_half = √(4A|cosθ|/π)/d /2 + β/2` จะต่างกันเมื่อ offset ของแผงย่อย (±25/±75 m) กับค่า θ ที่เล็กลง (A=100 vs 400 m²) ยังเทียบขนาดกับ β ไม่ได้: demo ที่ 5.4 km groups=4 ได้ 73 นาที vs groups=1 ได้ 50 (1.46×) แต่ที่ ~345 km เท่ากันทั้งคู่ (40 นาที) ฉะนั้นผล far-field เชื่อถือได้โดยไม่ต้องคำนวณซ้ำกับ groups ต่างๆ ส่วน receptor ที่ระยะใกล้-กลาง (เทียบได้กับแผงสูง 200 m) ต้องใช้ `groups>1` เพื่อความแม่น ติสำหรับ **ocular hazard** ใช้ `hazard_area` (surface ทั้งแผ่น) ดังนั้น x/E_r/G-Y-R ไม่เปลี่ยนตาม groups เลยไม่ว่าใกล้ไกล
- Folium HTML map needs internet for tiles (`environment.map_tiles` provider feed from `_MAP_TILES` in `viz.py`; committed value + code default `_MAP_TILES_DEFAULT` = `"esri_street"` — the yaml comment documents that default; carto also 403s in some browsers); the static PNG map is the offline fallback.
- **IEC 62471 α is foreshortened by |cos θ_ref-pva|**, not the geometric panel dims, to stay consistent with SGHAT's "visible extent" convention. Document this choice when comparing with third-party IEC assessments. **On the current config α is a CONSTANT 0.050850 rad for every receptor, and the reason is the 4,890 m row length, not the receptor distance.** `analysis.py:352-353` passes `width_m = array.width_m` = 2.0 m (panel depth) and `height_m = hazard_area/array.width_m` = 4,890 m (full row), and `angular_subtense` clamps each dimension to [α_min 0.0017, α_max 0.1] **before** averaging (iec62471.py:300-314). Over the active receptor range (array-CENTER distance 2.57 km for `obs_ptt` … 16.37 km for `west1_route_1`): 4,890/d = 0.30…2.93 rad ≫ α_max → the length term pins at 0.1; 2/d = 0.00012…0.00078 rad < α_min → the depth term pins at 0.0017; α = (0.1+0.0017)/2 = **0.050850** for all 9 committed case-receptor pairs (`iec_alpha_rad` distinct = 1 in every glare CSV). Consequences to state in any write-up: (a) α cannot distinguish receptors at all, so the tilt/azimuth sweep cannot move it; (b) because the length term saturates even at |cos θ| = 1, the `|cos θ|` foreshortening convention is **provably irrelevant** here — geometric and foreshortened α are identical at every distance; (c) the IEC retinal-thermal EL = 2.8e4/α = **5.506e5 W/m²/sr** is a single constant for the whole config, i.e. the most restrictive value this row can generate at any receptor distance (and it matches the ELV already used in the ICNIRP cross-check). (Former near-field vehicles at 10 m west of the row were **RG3 under either convention** — there 2/d = 0.2 also clamps high, so α = (0.1+0.1)/2 = 0.1 → RG2 EL 7.1e5, vs foreshortened α≈0.051 → 1.39e6; peak L_R=2.72e6 exceeds both.)
- **IEC spectral weights k_X use the FULL-spectrum normalisation** (`∫S dλ` over 200–4000 nm), not the per-clause band denominator, because E_c is broadband. The RG result is dominated by the **R(λ) action spectrum**, not the normalisation: using the standard's **full Table 4.2 R(λ)** (blue-violet hump, peak 10.0 at 435–440 nm) gives k_R = 1.290 — on the committed runs this is what puts **obs_ptt / west1_route_11 (az098 tilt 10) at RG3** (L_R 2.633e6/1.430e6 vs RG2 EL 1.396e6; route_11 has 20 of its 351 minutes at RG3, the rest RG2), whereas the older flat-R(λ) approximation (k_R = 0.476) or a band-normalised k_R (~0.55) both fall below the RG2 EL and give RG2 — while **west1_route_1 / west1_route_2 (az278) are RG2 either way** once τ cuts the far-field power. The wrong k_B/k_R makes the two hazard clauses inconsistent with each other and with any external auditor.
- **ICNIRP 2013 cross-check is independent evidence, not a second regulatory verdict** (`validate_icnirp.py`): the ICNIRP guideline has **no risk-group classification** and its R(λ) is flat=1.0 over the visible (k_R ≈ 0.587 vs IEC 1.290) — so the RG3 label comes from IEC 62471/BS EN only, while ICNIRP-derived numbers corroborate it asymmetrically: **az098 exceeds the steady EL under either weighting (obs_ptt 2.17×, west1_route_11 1.18×; ICNIRP transient t_max ≈ 0.0117/0.134 s), az278 is safe under both (west1_route_1 0.16×, west1_route_2 0.23×; steady t_max ≈ 411/87 s)**. Quote ICNIRP as "exceeds the ICNIRP steady exposure limit" only for the az098 near-field hits, not "ICNIRP RG3".
- **IEC `t_max_thermal` is the minimum across glare minutes for a receptor** (worst-case allowed exposure), reported per-receptor in `iec62471_summary.csv`. The per-minute values are in the detail `glare_hours_*.csv` files, one row per glare minute. `t_max` is the time for which the cumulative irradiance would produce the threshold retinal temperature rise — it is NOT an instantaneous duration limit; shorter stare durations are risk-free.
- Real site data goes into `config/site.yaml` (arrays/receptors) — no code changes needed.
